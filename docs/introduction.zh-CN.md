# Kuding Desktop MCP：从真实需求中打磨出来的 Windows 桌面自动化工具

[English](introduction.md) | **简体中文**

让 AI 打开软件、找到按钮、输入内容，再检查操作结果——这些能力正在让 AI 助手参与日常工作。我们开发 Kuding Desktop MCP（苦丁茶桌面 MCP），起点就是自己工作中的具体需求。

## 为什么在已有电脑控制工具时继续开发

项目开始时，ChatGPT 已经提供了电脑控制插件，我们也在使用。同时，我们使用的 WorkBuddy 环境中缺少专门控制本地电脑的插件或 MCP。我们希望其他支持 MCP 的 AI 客户端也能操作 Windows 软件，把需要人工点击、填写和检查的步骤交给 AI 协助完成。

随着使用深入，我们遇到了应用适配、工具可用范围和操作方式方面的限制。我们希望拥有一套能够自行检查代码、调整功能、积累软件操作经验的桌面工具，与 ChatGPT 官方电脑控制能力形成补充，也为其他 MCP 客户端提供选择。工具的使用仍需遵循用户授权和客户端自身的权限、审批规则。

## 从开源项目出发

Kuding Desktop MCP 基于 [Windows-MCP](https://github.com/CursorTouch/Windows-MCP) 0.8.5 开发。上游项目为开发提供了重要基础，我们保留原作者版权声明和 MIT 许可，并清楚说明项目来源及自己的改动。

开发过程中，我们尝试过在 Power BI 中制作看板，通过监控客户端界面导出资料，以及操作具有自绘界面的聊天软件。这些任务推动了具体改进：

- 全桌面扫描可能慢且漏控件，于是增加按窗口、进程限定范围的查找。
- 自绘界面不能提供完整控件树，于是结合本地 OCR 和截图辅助判断。
- 窗口遮挡、移动和布局变化会使旧坐标失效，于是增加截图与窗口归属检查。
- 点击发出后未必完成任务，于是提供操作后观察、条件等待和更明确的结果说明。
- 不同客户端和多人共用桌面会竞争输入，于是增加兼容实例间的互斥与真人输入让路机制。

每次改动尽量对应一个真实问题，并记录原因、处理方式和验证范围。本文概括的是开发经历；公开版当前的验证范围见 [验证说明](validation.md)。

## 移除上游自动遥测

采用的上游版本包含 PostHog 使用统计与错误报送实现。这类功能可帮助开发者了解使用情况并改进产品。考虑到实际桌面任务可能涉及内部文件和业务资料，我们移除了这套自动遥测发送实现。

公开版的处理包括：用本地诊断替换发送模块、保留工具必需的异步调度接口、省略 PostHog SDK，并在启动前检查替换是否仍然有效。兼容接口名称可能仍出现 `PostHogAnalytics`，但不会建立 PostHog 客户端或生成原来的持久化匿名编号。

工具不会通过原有 PostHog 遥测机制自动向上游统计服务发送调用或错误信息。内部测试阶段的运行日志回传说明和分发服务也未纳入公开版。问题反馈由使用者主动提交。

本地日志可用于排查问题，错误信息仍可能包含窗口标题或文件路径，分享前需要脱敏。AI 客户端可能把截图、界面文字交给其模型服务；安装更新和显式联网工具也有网络行为。这些行为与已经移除的上游遥测分别说明在 [PRIVACY.md](../PRIVACY.md)。

## 连接观察、操作和验证

在观察环节，工具优先读取 Windows UI Automation 提供的控件信息，遇到信息不完整的界面再结合截图和 OCR。

在操作环节，工具通过控件名称、类型、AutomationId，以及窗口、进程等条件定位目标。支持原生操作的控件可以直接调用写值、选择、展开等动作。

在验证环节，工具提供观察变化和等待条件的能力，帮助 AI 检查界面结果。动作已经发出、画面发生变化、业务目标完成，是需要分别确认的事情。

配套 skills 记录通用操作方法和常见问题，帮助 AI 选择合适的工具。工具与 skills 一起积累实践经验。

## 适用场景与开源目标

它面向希望用 AI 协助操作 Windows 软件的个人、开发者和小团队，尤其适合需要跨软件处理、界面步骤较多、缺少现成 API 的任务。

效果受到软件控件实现、桌面状态、Windows 权限、屏幕缩放和 OCR 支持影响。我们会公开已验证的场景和已知限制，欢迎通过真实案例继续完善。

我们希望 AI 操作 Windows 桌面时看得更清楚，遇到问题时说得更明白，完成任务时拿得出验证结果。
